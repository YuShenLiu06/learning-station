# Learning Station v0.1.0

在同一个本机学习空间阅读材料、向助教提问、做练习、保存笔记并安排复习。

完整功能与变化见 [更新记录](../../CHANGELOG.md)。

## 发布状态

当前版本尚未发布，尚未创建 v0.1.0 标签；下载附件与最终发布版本以正式发布页为准。

桌面目标为 macOS Apple Silicon，其他平台尚未验收；开发构建未进行 Developer ID 签名或公证。

## 使用前

- AI 功能需要自行配置获准使用的模型地址与密钥，模型调用遵循服务方的用途与计费规则。
- Anki 复习需要本机已有 Anki 与 AnkiConnect，未连接时可使用本机复习卡和 CSV 导出。
- 飞书通知需要配置本人的机器人并手动启动服务，配置步骤见 [飞书设置](../feishu-setup.md)。
- 工具权限默认关闭，HTML 仅静态预览，图片附件仅本机预览，应用退出或休眠时不保证准点提醒。

## 本次限定修复的手动验收

仅在单独建立的测试课程操作，不修改真实学习材料。

1. 向测试课程导入一份较小的 `large.txt`，确认可以正常预览，并保留另一份可正常读取的小材料。
2. 定位已导入附件的受管位置 `materials/assets/<courseId>/<assetId>/large.txt`，记录路径中的 `assetId`。
3. 在应用外将这份测试附件扩大至 5 MiB + 1 字节，保持文件位置与登记编号不变；不要直接导入超大文件，也不要扩大作为正文的业务笔记。
4. 开启请求调试，切回测试课程的普通笔记，发送一个新问题，再导出本轮请求记录。
5. 搜索 `capacity_exceeded`，确认该附件被排除、正文未送入请求，且 `excludedFiles.assetId` 或材料目录中的 `inventory.sourceId` 与步骤 2 的登记编号一致。
6. 确认普通材料仍可用于提问，超大附件不会阻断整次请求；完成后关闭请求调试。

自动测试已覆盖旧行为丢失附件编号的失败场景与修复后的结果，但以上原生界面操作尚未记录为通过。
